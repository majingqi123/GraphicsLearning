# 阶段 4：运行时引擎的最小集合

大约 16–20 周。这是你自己写的 Windows 运行时引擎，三个 API 走阶段 3 的 RHI。不做编辑器、物理、音频、网络和脚本。场景用 C++ 搭，或读 glTF。

功能按下面的顺序加。每加一项，三个 API 都看过画面，再进入下一项。详细的工程任务以后可以再拆一份实现计划，但产出和验收以这里为准。

## 学习目标

- 把主循环、时间步、输入、相机从各个 Demo 里收成固定结构。
- 网格、纹理、着色器有缓存，同一资源不重复上传。
- 材质、前向 PBR、一盏方向光阴影、IBL、色调映射跑在 RHI 之上，而不是在某个后端里写死。
- 能画出资源从文件到 GPU 的路径，以及阴影 pass 前后屏障在哪。
- GPU 调试名让 RenderDoc 里的 pass 能对上你的笔记。

## 学习产出

笔记：一张一帧的 pass 图，一张资源路径图。每加一个功能，在 pass 图上改一版，旧图留着。

你自己写的程序只有一个引擎可执行文件，用启动参数选 API。功能完成时打一个你自己认得的标签（提交或目录快照均可），方便回头看：

1. `loop`：窗口、主循环、时间步、键鼠相机。先清屏。
2. `gltf`：读一个 glTF，无光照或只有常量色，三个 API 姿态一致。
3. `cache`：同一个模型绘制两次，纹理和网格只上传一次。你可以打印上传次数来证明。
4. `forward`：金属-粗糙度直接光，先不接 IBL。
5. `shadow`：这盏方向光的阴影贴图。
6. `ibl`：辐照度、预滤波、BRDF LUT。
7. `tonemap`：HDR 场景加色调映射。
8. `markers`：RenderDoc 里能看到上述 pass 的名字。

这 8 步构成面试用的最小集合。完成后再按兴趣加，仍然三个 API 一起看：

- 延迟渲染、级联阴影、SSAO、Bloom
- 视锥剔除、实例化
- 骨骼动画、粒子、多线程录制命令缓冲、渲染图、GPU 剔除

后面这组不是本阶段的验收项。最小集合没过，不加它们。

## 学习安排

大约每两周一个编号。工作日只动当前编号，周末做三 API 对比。

- 第 1–2 周：`loop`
- 第 3–5 周：`gltf`。加载和坐标系最容易超时，预留一整周。
- 第 6–7 周：`cache`
- 第 8–10 周：`forward`
- 第 11–13 周：`shadow`
- 第 14–16 周：`ibl`
- 第 17–18 周：`tonemap` 和 `markers`
- 第 19–20 周：只做三 API 的截图对比和笔记，不加大功能。用来消化前面滑过去的周。

若某一项超过三周，砍掉该项里的可选项（例如先用一维粗糙度、先不做法线贴图），保证三个 API 都有画面，再在复盘里记下欠账。

- [GAMES104 第 4、5、7 讲](https://www.bilibili.com/video/BV1oU4y1R7Km/)：渲染实践、光和材质、管线与后处理。

- [LearnOpenGL 中文的 PBR 与 IBL](https://learnopengl-cn.github.io/) 当你忘记某张预计算纹理时用来回忆，不要把其中的 OpenGL 调用直接写进 RHI 上层。

英文：

- [Filament 材质文档](https://google.github.io/filament/Filament.md.html) 查能量项和 IBL。
- [RenderDoc](https://renderdoc.org/) 对三个 API 各抓一次最小集合的帧。

## 验收标准

- 同一个 glTF 场景，三个 API 各一张截图，光照方向、材质明暗和阴影位置一致。允许抗锯齿和极细的滤波差别，不允许缺一盏灯或阴影整张反了。
- RenderDoc 里能看到阴影、前向、色调映射这些名字。
- 你能白板画出 RHI、这一帧的 pass、文件到 GPU 的路径，以及阴影贴图从「深度写入」变成「着色器读取」的那一次屏障。
- 缓存可以用日志或断点证明：重复绘制没有重复上传。

## 自测

准备 15 分钟口述，下面 5 题都要能落到你的截图或抓帧上，不能只背定义。

1. 这一帧先画谁？如果把色调映射放到阴影之前，画面会怎样？
2. 材质参数住在哪一级缓存里，和网格缓存是不是同一个生命周期？
3. 方向光的阴影矩阵在 CPU 算还是在着色器里算？三个 API 是否共用这份矩阵？
4. IBL 的三张纹理在你的引擎里是启动时算的，还是从文件读的？它们算不算「资源缓存」的一部分？
5. 指出一次具体的屏障：在哪个 pass 结束，在哪个 pass 开始之前，资源从什么状态到什么状态。

## 复盘

- 8 个标签各自的日期，以及被砍掉的可选项。
- 三张截图和三次抓帧的文件名。
- 三个 API 中，哪一个最常在「画面错了但没有报错」里花时间。
- 最小集合的欠账列表。欠账可以成为阶段 5 的选题，也可以留到你以后的实现计划。
- 进入阶段 5 的条件：验收四条达到。欠账不影响进入，但欠账不能是「还没有阴影」或「只有一个 API」。
