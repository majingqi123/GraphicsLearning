# 阶段 5：对着自己的引擎加深

大约 8–12 周，按专题滚动。前提是阶段 4 的最小集合已经能在三个 API 上讲清楚。这一阶段不再堆系统，而是把面试里会被追问的点，讲到能指着自己的抓帧。

每两周只做一个专题。工作日读材料和回看抓帧，周末写一页口述稿，并改一个很小的实验。

## 学习目标

图形方向能讲清楚：

- 直接光和 IBL 的几何项为什么不是同一套参数。
- acne、peter panning，以及 bias、多边形偏移、把背面画进阴影贴图各压哪一种。
- 色调映射在压缩哪一段亮度。
- 你的 G-Buffer 若改成延迟，通道、精度和带宽怎么选。阶段 4 若仍是前向，这一题用阶段 1 的 `06_deferred` 或在引擎里加一个临时 pass。
- 一次真实的同步错误在 validation layer 或 PIX 里长什么样。

引擎方向能讲清楚：

- 你的网格、纹理缓存是句柄还是裸指针，释放时 GPU 是否还可能在用。
- 多帧并行时，哪一份常量缓冲正在被 GPU 读。
- 从一份 HLSL 到三个后端的路径；若要热重载，要重建的是管线还是整张纹理。
- 如果以后做渲染图，一张临时纹理何时创建、何时还能被下一个 pass 读。

bindless、mesh shader、DXR / Vulkan 光线追踪放到本阶段全部讲完之后，每个再单开至少两周。它们不是验收的一部分。

## 学习产出

每个专题一份口述稿，限制在你真的能讲 10 分钟的篇幅，并附上抓帧或截图文件名。

你自己写的小型实验，从下面挑，做完验收清单里的 4 个即可：

1. `shadow_bias`：同一场景，只改 bias 或偏移，导出 acne 和 peter panning 各一张图。
2. `gbuffer_cost`：记下你选的通道格式，并估算一帧这几张目标的字节数。改一种更低的法线精度，写下高光变化。
3. `sync_bug`：故意保留一个写错的屏障，把报错抄下来，再修复。不要把这个版本留在主线里。
4. `frames_in_flight`：把动态缓冲从 2 或 3 份改成 1 份，记录花屏或验证错误，然后改回。
5. `talk`：选上面任意一个，计时讲 10 分钟。可以只对录音讲。讲完把卡壳的句子写进复盘。

## 学习安排

- 第 1–2 周：阴影瑕疵，完成 `shadow_bias`。
- 第 3–4 周：PBR 的直接光和 IBL 差异。回看阶段 4 的着色器，改口述稿，不必新开大 Demo。
- 第 5–6 周：G-Buffer 或色调映射，二选一做深，另一个写成半页。若选 G-Buffer，做 `gbuffer_cost`。
- 第 7–8 周：同步与多帧，完成 `sync_bug` 和 `frames_in_flight` 里至少一个，另一个可以只写时序图。
- 第 9–10 周：把引擎路径（HLSL、缓存、屏障）收成一张图，做一次 `talk`。
- 第 11–12 周：弹性，用来补讲不顺的那一题。不要在这周开始光线追踪。

## 验收标准

- 至少 4 份口述稿，其中必须包含阴影瑕疵、同步或多帧、以及 HLSL 到三后端这条路径。
- 每个稿子都能指到你自己的图或报错，不是只引用教程插图。
- 一次 10 分钟讲述按时讲完。卡壳处已经写进复盘，并补了一句你现在能讲出的话。
- 阶段 4 的三个 API 仍然能跑。加深实验没有把主线引擎改坏。

## 自测

随机抽 3 题，每题 5 分钟，不允许翻口述稿。建议让日历提醒在两周后再抽一次。

1. 几何项在直接光和 IBL 里各用什么粗糙度形式？你的着色器现在用的是哪一种？
2. 给一张只有 acne 的图，你先动 bias、偏移，还是先改阴影贴图的分辨率？为什么？
3. 法线从 RGBA16F 改成八面体编码或 8 位，带宽和高光各会怎样？
4. fence 还没等到就覆写常量缓冲，画面和报错分别可能是什么样？
5. 热重载改了 HLSL 的纹理寄存器，三个后端里谁必须重建管线，谁还必须重建描述符布局？
6. 渲染图如果在这里引入，你现在的哪一次手写屏障会被资源依赖代替？代替之后生命周期谁来管？

6 题里当场讲清 4 题，并且每题都提到你的程序，这一阶段就可以告一段落。

## 复盘

每两周一次，五六行：

- 这两周的专题和实验名字。
- 讲述时卡住的原句。
- 改完之后的句子。
- 主线引擎有没有被实验改坏，怎么确认三个 API 仍能跑。
- 下一专题是否仍在清单内。若想改学光线追踪，先把验收里的 4 份口述稿补齐。

全部专题结束时再写一页总复盘：你现在能投递的岗位叙述是什么，最小引擎能演示到哪一步，欠账仍是哪三条。
